# RFC — count_yolo

## 架构

```text
视频帧 → YOLO 检测 + ByteTrack
      → 轨迹中心点
      → L1 过线 / L3 entry-exit
      → 车型映射 → JSON →（未做）Excel
```

YOLO 只认车和粗分类。转向不靠车头角，靠几何：L1 用线 + 运动方向；L3 用进口区进入、出口区离开，再查 `movement_map`。每辆车只计一次。

源码在 `src/count_yolo/`。`pipeline.py` 依赖 ultralytics，按需导入，所以 CI 不必装 torch。几何、车型映射、GT 比对是纯函数，单测只覆盖这三块。

## 分层验收

| 层级 | 测什么 | 何时使用 |
|------|--------|----------|
| L1 | 单方向过线 | 任何素材先跑，验证检测-跟踪-计数链路 |
| L2 | 单走廊 O-D | L1 通过后可选 |
| L3 | 四进口全矩阵 | 机位近、遮挡少、标准十字口 |

L1 通过推不出 L3。示例匝道视频远景加桥墩，entry→exit 完整轨迹经常为 0，因此只发表 L1。

## 关键决策

1. **验收跟素材走，不跟愿望走。** 全矩阵是业务目标，不是每段视频的合格线。
2. **方向过滤优于空间裁剪。** 示例路段有潮汐车道，收窄 x 会漏同向车；用近期 `cy` 轨迹判断 near_to_far / far_to_near。
3. **结果级互补，而不是硬训一个全能权重。** COCO yolov8m 负责四轮，电自专用权重补摩托。当前是两次推理事后加总，单遍 fuse 未做。
4. **置信度下限 0.25。** 0.15 全片结果与 0.25 相同，瓶颈在召回边界。
5. **公开仓库与运行时数据分开。** 权重、视频、xlsx、debug mp4 不入库。JSON 合同只保留文件名。

## 运行时边界

计数需要 `.[runtime]`（ultralytics / opencv / lap）。默认 `.[dev]` 只有 numpy + pytest。Python 可执行文件由 `.venv` 或 `COUNT_YOLO_PYTHON` 提供，代码里不写其它项目的 venv 路径。

## 迁移

根目录三个 `.py` 和 `run.ps1` 保留为薄包装，旧命令继续可用。新逻辑只进 `src/`。
