检测与跟踪（遮挡丢 ID 时调这里）

视频里每辆车有一个跟踪 ID（debug 视频绿框上的数字）。车被挡住、框消失几帧后，若 ByteTrack 等太久就会丢掉旧 ID，再出现时常变成新 ID——未过线的车可能漏计。 下面参数分两类：检测（YOLO 能不能框到车）和跟踪（框消失后 ID 能不能接上）。

检测（YOLO）

是什么：只有得分 ≥ 此值的检测框才会参与跟踪。
怎么调：遮挡、漏检多时略降（如 0.25→0.2→0.15），让「露出一半的车」也能被框到；降太多会增加误检和杂框。

是什么：两个框重叠超过此比例时，去掉得分较低的那个（去重）。
怎么调：一般保持 0.7。拥堵贴在一起时略升高可少删框，但可能同一辆车留两个框。

是什么：每隔 N 帧才做一次检测（1=每帧都检测）。
怎么调：遮挡、跟丢 ID 时务必保持 1。设为 2 以上会跳帧，车移动幅度变大，更容易断轨；仅全片太慢、且场景简单时可试 2。

跟踪（ByteTrack）

是什么：检测框消失后，仍把这条轨迹「挂着」等它回来的最长帧数。超过就彻底丢掉旧 ID。
怎么调：遮挡丢 ID 时优先加大（默认 30 → 试 60、90、120）。越大越能扛遮挡，但车真的离开画面后，旧 ID 占得更久，偶发误关联风险略升。

是什么：重现的框与「挂着」的旧轨迹，位置要有多像（IoU）才算同一条车。
怎么调：车从遮挡里出来时框位偏了、接不上旧 ID 时，可略降（0.8→0.75→0.7）；太低会把相邻两辆车误并成一条。

是什么：ByteTrack 第二阶段：用「不太自信」的检测框去尝试接回已丢失的轨迹（遮挡恢复靠这个）。
怎么调：遮挡后 ID 经常断时略降（0.1→0.05）；太低可能用噪声框错误续轨。

是什么：第一阶段：多自信的检测框才参与和现有轨迹的匹配。
怎么调：一般保持 0.25。杂框、误跟踪太多时可略升；与 conf 配合，通常先动 conf 和 track_buffer。

是什么：检测框得分达到此值、又匹配不上任何旧轨迹时，才新开一个 ID。
怎么调：一般保持 0.25。路边静态物被当成车、ID 乱跳时可略升；真正新车进画面晚出现时可略降（慎用）。

建议调试顺序：① 抗遮挡预设 → 保存 Job → 试跑 30s → 看 debug 里 ID 是否更连贯 → ② 仍断 ID 则继续加大 track_buffer → ③ 仍漏检框则略降 conf / track_low_thresh。改完务必保存 Job。

首次使用流程
  1. 填写本机视频路径与断面名称（如 L1_主路,L1_匝道）
  2. 点「标定断面」→ 弹出 OpenCV 窗口，左键两点画线，按 n 确认
  3. 标定完成后回到本页刷新，勾选断面，播放标定预览片验收
  4. 线位不对可点「重绘」重新标定
  5. 确认无误后点「全量计数」
